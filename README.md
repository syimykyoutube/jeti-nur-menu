# Жети Нур Меню

Кафелер үчүн QR меню долбоору. Талаптардын толук булагы — [TZ.md](TZ.md).

Азыр база, авторизация, KY/RU кирүү бети, супер админ панели жана owner үчүн
категорияларды, тамактарды, өлчөмдөрдү, бааларды жана сүрөттөрдү башкаруучу панель даяр.
Кафе жөндөөлөрүнөн логотип, аталыш жана менюнун демейки тили өзгөрөт. `GET /` сурамы
`Жети Нур Меню` деген текст кайтарат. Кардарлардын `/{slug}` менюсу даяр HTML
менен ачылат, KY/RU которулат жана биринчи толук ачылгандан кийин офлайн иштейт.
Админдеги «QR код» экраны SVG жана басмага ылайык PNG жүктөп берет.
Кабыл алуу критерийлеринин ар бири [өзүнчө отчётто](reports/definition-of-done.md)
текшерилди. Жандуу сайт: <https://jeti-nur-menu.jeti-nur-menu.workers.dev>.
Продакшн текшерүүлөрүнүн абалы [деплой отчётунда](reports/deployment.md).

## Керектүү программалар

- Node.js 24 LTS (npm кошо келет).
- git.

Версияларды текшерүү:

```sh
node --version
npm --version
git --version
```

Эгер жок болсо, Node.js LTS'ти <https://nodejs.org/en/download> дарегинен орнотуңуз.
macOS'то git жок болсо, `xcode-select --install` буйругун аткарып, ачылган терезеде
Command Line Tools'ту орнотуңуз. Орноткондон кийин терминалды кайра ачыңыз.

## Орнотуу

Терминалда ушул долбоордун папкасында аткарыңыз:

```sh
npm ci
```

Бул буйрук `package-lock.json` файлында бекитилген версияларды орнотот.
Hono — сурамдарды иштетүүчү жеңил китепкана. TypeScript коддогу типтерди текшерет.
Wrangler жана Cloudflare типтери иштеп чыгуу үчүн гана колдонулат.
Vitest баа, slug, база жана авторизацияны текшерет. Miniflare — Wrangler колдонгон
Cloudflare локалдык эмулятору; тесттер аны менен өзүнчө убактылуу D1 базасын жана R2 сактагычын ачат.
Wrangler долбоордун ичинде орнотулат, глобалдык орнотуу талап кылынбайт.

## Компьютерде иштетүү

Биринчи иштетүүдө ушул иретти колдонуңуз:

```sh
npm ci
npm run secrets:local
```

Редактордон `.dev.vars` файлын ачып, бош `SETUP_LOGIN` жана `SETUP_PASSWORD`
маанилерин өзүңүз толтуруңуз. `PASSWORD_VIEW_KEY` автоматтык түзүлөт; аны сактаңыз.
Андан кийин:

```sh
npm run db:migrate:local
npm run menu:rebuild:local
npm run dev
```

`menu:rebuild:local` мурдагы кафелердин даяр HTML'ин жаңылайт; жаңы бош базада
эч нерсе өзгөртпөйт. Сервер иштегенде `/admin/setup` дарегинен биринчи супер
админди түзүңүз. Төмөндө толук түшүндүрмө бар.

Кийинки иштетүүлөрдө:

```sh
npx wrangler dev
```

Же ошол эле ишти аткарган кыска буйрук:

```sh
npm run dev
```

Терминалда көрсөтүлгөн даректи браузерден ачыңыз. Демейки дарек:
<http://localhost:8787>. Экранда `Жети Нур Меню` чыгышы керек.
Серверди токтотуу үчүн `Ctrl+C` басыңыз.

Башка терминалдан жоопту текшерсеңиз болот:

```sh
curl -i http://localhost:8787/
```

Күтүлгөн жыйынтык: `200 OK`, `text/plain` жана `Жети Нур Меню` тексти.

TypeScript текшерүүсү:

```sh
npm run typecheck
```

Тесттерди иштетүү:

```sh
npm test
```

Эгер компьютер жүктөлүп турганда интеграциялык тест `Test timed out in 5000ms`
деп токтосо, эмуляторлорду кезек менен иштетип, күтүү чегин 15 секунд кылыңыз:

```sh
npm test -- --no-file-parallelism --testTimeout=15000
```

Бул локалдык тесттин күтүү мөөнөтү. Менюнун Slow 3G ылдамдыгы Lighthouse менен
жандуу URL'де өзүнчө өлчөнөт.

Тесттерге Cloudflare аккаунту жана интернет талап кылынбайт. Убактылуу тест
базасы негизги `.wrangler/` маалыматтарын өзгөртпөйт жана тесттен кийин жабылат.
Эмулятор локалдык порт ачкандыктан, чөйрө localhost байланыштарына уруксат бериши керек.

## D1 жана R2 жөндөөлөрү

ТЗда binding жана сактагычтардын так аттары берилген эмес. Бул долбоордо:

| Кызмат | Коддогу binding | Ресурстун аты |
| --- | --- | --- |
| D1 маалымат базасы | `DB` | `jeti-nur-menu` |
| R2 сүрөт сактагычы | `IMAGES` | `jeti-nur-menu-images` |

Алар `wrangler.toml` файлында жана `src/types.ts` типтеринде көрсөтүлгөн.
Миграциялар: `migrations/0001_init.sql`, `0002_auth.sql`, `0003_images.sql`, `0004_public_menus.sql`.

`wrangler.toml` ичиндеги `database_id` — бул долбоор үчүн түзүлгөн чыныгы Cloudflare
D1 базасынын ID'си. Башка аккаунтка орнотсоңуз, өзүңүз түзгөн базанын ID'сине алмаштырыңыз.
`wrangler dev` D1 жана R2'ни компьютерде иштетет; Cloudflare аккаунту жана булуттагы
ресурстар талап кылынбайт. Жергиликтүү абал `.wrangler/` ичинде сакталат.

## Локалдык базаны даярдоо

```sh
npx wrangler d1 migrations apply jeti-nur-menu --local
```

Же:

```sh
npm run db:migrate:local
```

Ырастоо суралса, `y` басыңыз. Миграция 7 таблицаны жана алардын индекстерин түзөт:
`cafes`, `users`, `sessions`, `categories`, `items`, `item_variants`, `published_menus`.
Экинчи миграция IP боюнча логин чектөөсүнүн ички `auth_rate_limits` таблицасын,
бир супер админ/кафеге бир owner эрежесин жана сессияларды өчүрүүчү триггерлерди кошот.
Үчүнчү миграция сүрөттөрдүн кафеге таандыктыгын, бир жолу колдонулушун жана
эски файлдарды тазалоо кезегин сактаган `image_uploads` таблицасын кошот.
Wrangler колдонулган миграцияны эстеп калат; кайра аткарсаңыз аны кайталап түзбөйт.
Бул буйрук компьютердеги базага гана тиешелүү, Cloudflare аккаунту талап кылынбайт.

`slug`, `login` жана сессия токенинин хэши уникалдуу. `cafe_id`, `category_id`,
`item_id`, `user_id` жана иреттөө боюнча керектүү индекстер бар. ТЗга ылайык email
талаасы жок; анын ордуна `login` колдонулат.
ТЗдагы жети таблицада UTC `created_at` жана `updated_at` бар. ТЗдагы атайын талап
боюнча `published_menus` таблицасынын негизги ачкычы — `cafe_id`; калганында — `id`.

## База функциялары

`src/db/types.ts` — таблица катарларынын жана киргизилүүчү маалыматтардын TypeScript типтери.
`src/db/queries.ts` — кафе, категория, тамак жана вариант үчүн `create`, `get`,
`list`, `update`, `delete` функциялары. Кафени slug менен алуу үчүн `getCafeBySlug` бар.
Бардык киргизилген маанилер SQL'ге `bind()` параметрлери менен берилет.
Өзгөртүлчү таблица жана талаа аттары коддогу уруксат берилген тизмеден гана алынат.

Категория, тамак жана вариант функциялары `cafeId` талап кылат. HTTP маршруттар
сессияны жана кафеге кирүү укугун текшергенден кийин гана бул функцияларды чакырат.
`src/db/admin.ts` кафе+owner түзүү, логин/паролду өзгөртүү, кафени токтотуу жана
супер админ үчүн паролду ачуу операцияларын аткарат.

- `createItem` кеминде бир вариант талап кылат. Тамак жана анын варианттары бир
  транзакцияда түзүлөт: бирөө жараксыз болсо, баары артка кайтарылат.
- `update` функцияларына өзгөрө турган талааларды гана бериңиз. Берилбеген
  талаалар сакталат, орусча текст же сүрөт ачкычы сыяктуу кошумча талааларды
  тазалоо үчүн `null` берсе болот. `updated_at` автоматтык түрдө жаңыланат.
- Туура эмес кафе же жок катар үчүн `get`/`update` `null`, `delete` `false` кайтарат.
  Вариант түзүүдө да тамак ошол кафеде жок болсо, `null` кайтат.
- `deleteVariant` тамактын акыркы вариантын өчүрбөйт (`false` кайтарат).
- `deleteCategory` үчүн `{ action: 'delete-items' }` же
  `{ action: 'move-items', targetCategoryId: ... }` тандоосу милдеттүү.
  Көчүрүү ошол эле кафенин башка категориясына гана мүмкүн.
- Кафени өчүрүү ага байланыштуу база катарларын да өчүрөт. Тамак өчүрүлсө,
  анын варианттары да өчөт. HTTP админ маршруттары өчүрүлгөн тамактардын
сүрөттөрүн R2'ден да тазалайт. DB функцияларын түз чакырсаңыз, андан кийин
`cleanupImages(env, cafeId)` чакырыңыз; өчүрүлчү сүрөттөрдүн кезеги D1'де сакталат.

`src/lib/price.ts`: `formatPrice(180)` → `180 сом`. Баа терс эмес, коопсуз бүтүн
сан болушу керек; бөлчөк, `NaN`, чексиз же өтө чоң сан четке кагылат.
`src/lib/slug.ts`: `isValidSlug` 3–40 белгиден турган `a-z`, `0-9`, тирени гана
кабыл алат. Өзүнөн өзү боштуктарды тазалабайт жана тамгаларды өзгөртпөйт.

## Сырлар жана git

Жергиликтүү сырлар `.dev.vars` файлына жазылат. Аны git'ке кошпоңуз.
`.dev.vars.example` ичинде сырсыз үлгү бар; чыныгы ачкыч же пароль анда болбошу керек.
`.dev.vars`, `.env`, `node_modules/` жана `.wrangler/` `.gitignore` ичинде бар.
`package-lock.json` версияларды бирдей кармоо үчүн git'ке кошулат.

## Биринчи супер админ менен баштоо

1. `npm run db:migrate:local` менен бардык локалдык миграцияларды колдонуңуз.
2. `npm run secrets:local` аткарыңыз. Буйрук `.dev.vars` файлын жана 32 байттык
   кокус `PASSWORD_VIEW_KEY` ачкычын түзөт. Ачкыч экранга чыгарылбайт. Файл
   мурда бар болсо, ал өзгөртүлбөйт.
3. Редактордон **`.dev.vars`** файлын ачыңыз. `SETUP_LOGIN=""` жана
   `SETUP_PASSWORD=""` саптарына биринчи супер админдин өзүңүз тандаган
   логинин жана паролун жазыңыз. Логин: 3–40 белги (тамга, сан, нокот, тире,
   астыңкы сызык); пароль: 8–128 белги. `PASSWORD_VIEW_KEY` маанисин өзгөртпөңүз.
4. `npm run dev` иштетиңиз. <http://localhost:8787/admin/setup> дарегин ачыңыз.
   Даярдаган логин/паролуңузду киргизип, аккаунтту түзүңүз.
5. `/admin/login` бетинде ошол логин/пароль менен кириңиз. Супер админ панели
   ачылат. Эми `.dev.vars` ичиндеги `SETUP_LOGIN` жана `SETUP_PASSWORD` саптарын
   өчүрүп, серверди кайра иштетсеңиз болот.

Супер админ түзүлгөндөн кийин `/admin/setup` GET жана POST үчүн тең 404 кайтарат.
Сырлар коюлбаса, setup жабык бойдон турат. Бир убакта эки сурам келсе да бир
супер админ гана түзүлөт. Өзү катталуу жана пароль калыбына келтирүү формалары жок.

`PASSWORD_VIEW_KEY` файлын коопсуз сактаңыз. Ал мурда шифрленген owner паролдорун
ачууга керек; аны жоготсоңуз же алмаштырсаңыз, ошол паролдорду көрсөтүү мүмкүн болбойт.
Мындай учурда супер админ owner'ге жаңы пароль коюшу керек. Логинди текшерүү
үчүн колдонулган PBKDF2 хэштери бул ачкычтан көз каранды эмес.

2026-10-16 күнү өндүрүштөгү ачкыч жаңыртылды. Учурдагы өндүрүш ачкычынын
локалдык көчүрмөсү — git'ке кирбеген `cloudflare-secrets.env` файлы.
`.dev.vars` локалдык база үчүн; `.dev.vars.production` эски көчүрмө болгондуктан
аны өндүрүшкө кайра жүктөбөңүз. Жандуу `jeti-nur-demo` тест кафесинде супер
админ «Логин/паролду өзгөртүү» аркылуу паролду толтуруп, кайра сакташы керек.
Бош пароль калтырсаңыз эски шифр жаңырбайт. Анан «Көрсөт»/«Көчүр» текшериңиз;
owner бардык түзмөктөрдө кайра кирүүгө тийиш. Супер админдин өз паролу өзгөргөн жок.

## Админ панелин колдонуу

- `/admin/login` — логин жана пароль, KY/RU тил тандоосу. Тил колдонуучунун
  `ui_lang` талаасында сакталат.
- `/admin/super` — кафелердин саны, тизмеси, логини, жашырылган паролу,
  түзүлгөн убактысы (Бишкек убактысы) жана иштөө абалы.
- «Жаңы кафе» бөлүмүндө атын, slug, owner'дин логин/паролун **өзүңүз кол менен**
  киргизесиз. Кафе менен owner бирге түзүлөт; сактоодо ката болсо, экөө тең түзүлбөйт.
- «Көрсөт»/«Көчүр» паролду супер админге гана ачат. Ал баштапкы HTML'де болбойт.
  Көрсөтүлгөн пароль 30 секунддан кийин же беттен башка жакка өткөндө жашырылат.
- Логин/пароль өзгөргөндө же кафе токтотулганда owner'дин бардык сессиялары
  ошол эле база операциясында өчөт. Башка түзмөктөгү кийинки сурамда да кайра
  кирүү талап кылынат. Кафе кайра иштетилсе, эски сессиялар калыбына келбейт.
- «Кафеге кирүү» `/admin/cafes/:cafeId` бетин ачат. Супер админ ал жерде
  категория, тамак жана бааларды түзүп/оңдой алат. Owner өзүнүн кафесине гана кирет.
  Сүрөттөр да ушул панелден жүктөлөт; сакталган өзгөрүүлөр коомдук менюга жарыяланат.

## Owner үчүн менюну башкаруу

Owner киргенде `/admin` автоматтык түрдө анын кафесинин панелине алып барат.
Бет 360px экранга ылайыкталган, баскычтары чоң; HTML серверде даярдалат,
React/Vue же башка UI фреймворктор колдонулбайт.

- Башкы экранда категориялар, алардын тамактары жана бардык баалар көрүнөт.
  Ар тамактын жанындагы «Бүттүбү?» которгучу «Жок» же «Бүттү» абалын көрсөтөт.
  Бир басканда JS `fetch` менен сакталат, бет жаңыланбайт. Ката болсо абал
  өзгөрбөй, түшүнүктүү билдирүү чыгат. JS өчүк болсо кадимки форма иштейт.
- «Категория кошуу» атын KY/RU менен киргизет. «Категорияны оңдоо» атын өзгөртөт.
  «Жогору»/«Ылдый» баскычтары ошол кафенин категорияларын гана иреттейт.
- Категорияны өчүрүүдө тамактарды кошо өчүрүү же башка категорияга көчүрүү
  тандоосу милдеттүү. Көчүрүү үчүн ушул кафенин башка категориясы тандалат.
- «Тамак кошуу» жана «Оңдоо» өзүнчө форма ачат: аты KY/RU, категория, курамы
  KY/RU, абалы, өлчөмдөрү жана баалары. «+ Өлчөм кошуу» кошумча сап ачат.
  Акыркы сапты алып салууга болбойт. «Сактоо» тамак менен бааларды чогуу сактайт.
- Баа терс эмес бүтүн сом болот. Бир вариант болсо, өлчөмдүн атын бош калтырса болот.
  Кыргызча аты милдеттүү; орусчасы бош болсо башкы экранда кыргызчасы көрүнөт.
- Бардык UI сөздөрү, анын ичинде JS билдирүүлөрү жана валюта, `src/lib/i18n.ts`
  ичинде. KY/RU тандоосу `users.ui_lang` ичинде сакталат.

Сервер да текшерет: аталыш 1–120 белги, курамы ар тилде 2000 белгиге чейин,
өлчөмдүн аты 40 белгиге чейин, бир тамакта 1–50 вариант, баа коопсуз бүтүн сан.
Бөтөн кафенин категориясына/тамагына/вариантына сурам четке кагылат.
Формадагы баа жараксыз болсо, киргизилген маалыматты оңдоо үчүн форма кайра ачылат.

## Меню версиясы жана автоматтык жарыялоо

`src/lib/publish.ts` ичиндеги `publishMenu(db, cafeId)` `menu_version` санын көтөрүп,
кафенин толук HTML менюсун `published_menus` таблицасына сактайт. CSS жана
эки тил беттин ичинде; шрифт — system-ui. Админге жооп кайтарылганга чейин
жаңы HTML даяр болот. Кафе түзүлгөндө бош меню да автоматтык жарыяланат.

Меню CRUD функциялары өзгөртүүлөрүн ушул функцияга берип, D1 `batch`
транзакциясында маалыматты жана версияны бирге сактайт. Бир тамактын бардык
өлчөмдөрүн сактоо же категорияны ичиндеги тамактары менен көчүрүү/өчүрүү бир
операция болуп эсептелет: версия бирге көтөрүлөт. Транзакциядагы ката
өзгөртүүнү жана версияны артка кайтарат. HTML өзүнчө, версияны текшерген SQL менен
сакталат: кечигип бүткөн эски сурам жаңы менюну басып калбайт.
Эгер ушул акыркы сактоодо байланыш үзүлсө, сурам ката берет; кайра сактоо же
`npm run menu:rebuild:local` менен локалдык даяр беттерди калыбына келтирүүгө болот.
Тез которгучтун ошол эле абалга кайталанган сурамы, чекке жеткен категорияны
жылдыруу аракети же четке кагылган сурам версияны көтөрбөйт. UI тилин өзгөртүү
да меню версиясына таасир бербейт.

## Авторизациянын иштеши

`src/lib/auth.ts` WebCrypto PBKDF2-SHA-256, 100 000 итерация жана ар пароль үчүн
өзүнчө кокус туз колдонот. Owner'дин көрсөтүлчү паролу AES-256-GCM менен, ар
шифрлөөгө жаңы nonce колдонуп сакталат. Супер админдин өз паролу хэш түрүндө гана сакталат.

Сессия токени 32 кокус байттан түзүлөт; базада SHA-256 хэши гана сакталат.
`__Host-jeti_session` cookie'си `HttpOnly; Secure; SameSite=Lax; Path=/`, мөөнөтү 30 күн.
Чыгууда базадагы сессия жана cookie өчүрүлөт. Ар бир корголгон сурамда база кайра
текшерилет: сессия барбы, мөөнөтү өтпөдүбү, колдонуучу барбы жана owner'дин кафеси активдүүбү.
Колдонуучунун өзүнчө `is_active` талаасы ТЗда жок; кафе аркылуу токтотулат.

POST/PUT/PATCH/DELETE үчүн `Origin` ушул сайттын дарегине так дал келиши керек.
Origin жок сурамдар да четке кагылат. `curl` менен форманы текшергенде
`Origin: http://localhost:8787` башын кошуңуз. Логин жана setup үчүн бир IP'ден
60 секундда 10 аракетке чейин уруксат; андан кийин 429 жана `Retry-After` берилет.
Лимит D1'де сакталат, Worker кайра иштегенде жоголбойт. IP үчүн Cloudflare койгон
`CF-Connecting-IP` колдонулат; локалда ал жок болсо бир жалпы чектөө иштейт.

Админ жооптору жана пароль endpoint'и `Cache-Control: private, no-store` менен
берилет. Колдонуучунун тексти HTML'ге чыгарууда escape кылынат. Сырлар, пароль
жана форма мазмуну логго жазылбайт. Кокус ички каталар да паролду жоопко чыгарбайт.

Локалда заманбап браузерден `localhost` дарегин колдонуңуз. Cookie'нин Secure
талабы өзгөртүлбөйт. Деплойдо HTTPS милдеттүү.

## Cloudflare'ге деплой кылуу

Төмөндөгү буйруктар сайтты интернетке чыгарат. Бул долбоор 2026-10-15 күнү
<https://jeti-nur-menu.jeti-nur-menu.workers.dev> дарегине чыгарылды.
D1 жана R2 буга чейин түзүлгөн: ушул аккаунтта аларды кайра түзүүнүн кереги жок.
Төмөнкү биринчи орнотуу кадамдары жаңы аккаунт үчүн көрсөтүлгөн.

Cloudflare аккаунту даяр болгондо:

```sh
npx wrangler login
npx wrangler whoami
npx wrangler d1 create jeti-nur-menu
```

Кайтарылган чыныгы `database_id` маанисин `wrangler.toml` файлына көчүрүңүз.
Эгер Wrangler конфигурацияга binding кошуп берсе, `DB` жазуусу бирөө гана
калганын текшериңиз. Андан кийин R2 сактагычын түзүп, Worker'ди чыгарыңыз:

```sh
npx wrangler r2 bucket create jeti-nur-menu-images
npx wrangler d1 migrations apply jeti-nur-menu --remote
npx wrangler deploy
```

Binding аттары `DB` жана `IMAGES` бойдон калсын. R2 Cloudflare аккаунтунда
иштетилген болушу керек. Терминалда чыккан `https://jeti-nur-menu.<атыңыз>.workers.dev`
дарегин сактаңыз. Сырлар коюла электе `/admin/setup` жабык болот.

Локалдык `.dev.vars` Cloudflare'ге автоматтык көчүрүлбөйт. Төмөнкү буйруктардын
ар бири маани киргизүүнү сурайт; сырды буйруктун өзүнө кошпоңуз:

```sh
npx wrangler secret put PASSWORD_VIEW_KEY
npx wrangler secret put SETUP_LOGIN
npx wrangler secret put SETUP_PASSWORD
```

Же үч сырды биринчи деплой менен бирге берсеңиз болот. Бул орнотууда
git'ке кирбеген `cloudflare-secrets.env` файлы колдонулат:

```sh
npx wrangler deploy --secrets-file cloudflare-secrets.env
```

Файлда `PASSWORD_VIEW_KEY` (32 байттык base64url ачкыч), `SETUP_LOGIN` жана
`SETUP_PASSWORD` болсун. Акыркы экөөнү өзүңүз жазыңыз; бул чатка жазылбайт.
Бул файл автоматтык жүктөлбөйт, `--secrets-file` атайын көрсөтүлгөндө гана
Cloudflare'ге secret катары жөнөтүлөт. Ачкыч файлда жана репозиторийден тышкаркы
коопсуз көчүрмөдө сакталсын. R2 API 10042 катасын берсе, Dashboard → Storage &
databases → R2 → Overview бөлүмүндө R2'ни өзүңүз иштетиңиз.

`PASSWORD_VIEW_KEY` үчүн `.dev.vars` файлыңыздагы 32 байттык base64url ачкычты
колдонсоңуз болот. Аны git'ке же билдирүүлөргө чыгарбаңыз. `secret put` Worker'ди
жаңы сыр менен кайра чыгарат. Локалдык база жана R2 сүрөттөрү булутка көчпөйт:
булуттагы бош база үчүн сайттын `/admin/setup` дарегинде супер админди түзүңүз.
Андан кийин баштапкы эки сырды алып салыңыз:

```sh
npx wrangler secret delete SETUP_LOGIN
npx wrangler secret delete SETUP_PASSWORD
```

`PASSWORD_VIEW_KEY` өчүрүлбөйт. Owner паролдорун ачуу үчүн аны коопсуз сактаңыз.
Сайттын HTTPS дарегинен кафе түзүп, owner менен сүрөт жана бааларды кошуңуз.
Ошол сайттан QR жүктөп, телефондон скан кылыңыз. KY/RU, «Бүттү», офлайн экинчи
ачылыш жана башка түзмөктөгү сессиянын токтошу булутта кайра текшерилсин.
Доменди алмаштырсаңыз, басмага жаңы QR бериңиз.

Код өзгөргөн кийинки деплойдо: `npm ci`, `npm test`, `npm run typecheck`, зарыл
болсо `npx wrangler d1 migrations apply jeti-nur-menu --remote`, анан
`npx wrangler deploy`. Мурдагы миграцияларды өзгөртпөй, жаңы файл кошуңуз.
Мурдагы кафелердин HTML'ин рендерер өзгөргөндөн кийин жаңылоо үчүн аларды
админден кайра сактаңыз; локалдык rebuild скрипти булуттагы базага иштебейт.

[Wrangler D1 буйруктары](https://developers.cloudflare.com/workers/wrangler/commands/d1/)
жана [Worker/secret буйруктары](https://developers.cloudflare.com/workers/wrangler/commands/workers/).

## Сүрөт жүктөө жана логотип

1. `/admin` аркылуу кириңиз. Тамактын «Оңдоо» бетин же «Кафе жөндөөлөрү»н ачыңыз.
2. Сүрөт тандаңыз: баштапкы файл 5 МБдан чоң болсо да болот. `public/admin.js`
   браузердеги canvas менен узун жагын тамак үчүн 640 px, логотип үчүн 256 px
   чегине чейин кичирейтет. Кичине сүрөт чоңойтулбайт; тараптардын катышы сакталат.
3. Сүрөт WebP форматына 0.75 сапат менен өтөт. Өтө деталдуу сүрөт 100 КБдан
   ашса, сапат төмөндөтүлөт, дагы эле батпаса өлчөмү да кичирейтилет. Натыйжа
   100 × 1024 байттан ашпайт. Форма баштапкы/акыркы көлөмдү, өлчөмдөрдү
   жана жүктөө жүрүшүн көрсөтөт. Жүктөлүп жатканда «Сактоо» убактылуу өчүк.
4. «Жүктөлдү» чыккандан кийин «Сактоо» басыңыз. Ошондо сүрөт тамакка/логотипке
   бекитилип, `menu_version` бирге көтөрүлөт жана мурдагы файл R2'ден өчөт.
   «Сүрөттү алып салуу» да «Сактоо» басылганда гана күчүнө кирет.

`POST /admin/upload` — сессия, Origin жана кафе укугун текшерген multipart API.
Талаалар: `cafe_id`, `kind` (`item` же `logo`), `file`. Сервер WebP/PNG MIME'ин,
файлдын башкы формат белгилерин жана **300 × 1024 байт** чегин текшерет.
Башка форматтар, бош/өтө чоң файлдар четке кагылат. Ачкычта cafe ID, кокус бөлүк
жана файлдын SHA-256 хэши бар; колдонуучунун файл аты сакталбайт.

Сүрөт жүктөө аны дароо менюга бекитпейт. Жараксыз форма мурдагы сүрөттү өчүрбөйт.
D1 триггерлери бир ачкычты башка кафеге/тамакка кайра бекитүүгө жол бербейт.
R2 убактылуу жеткиликсиз болсо, эски файл тазалоо кезегинде калат жана кийинки
ийгиликтүү өзгөртүүдө кайра өчүрүлөт. Сакталбай ташталган жүктөмдөр 24 сааттан
кийин ошол кафеде кийинки жүктөө же ийгиликтүү өзгөртүү учурунда тазаланат.

`GET /img/:key` сүрөттү R2'ден логинсиз берет:
`Cache-Control: public, max-age=31536000, immutable`, туура MIME, `nosniff`, ETag.
Сүрөт алмашкан сайын URL өзгөрөт. `public/admin.js` Wrangler'дин статикалык
файл кызматы аркылуу берилет; тышкы CDN же UI китепкана кошулган жок.
[Cloudflare статикалык файлдар нускамасы](https://developers.cloudflare.com/workers/static-assets/binding/)
жана [R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).

Локалдык текшерүүдө `npm run db:migrate:local`, анан `npx wrangler dev` аткарыңыз.
D1 жана R2 компьютерде симуляцияланат; Cloudflare аккаунту талап кылынбайт.
`npm test` сүрөт жүктөө, көлөм/түр чектери, кафе укугу, кэш, сүрөт алмаштыруу,
форма катасында артка кайтаруу жана тазалоону өзүнчө D1/R2 сактагычында текшерет.

Бул этаптын локалдык текшерүүсү: 8 404 028 байттык (2000×1400 px) синтетикалык
PNG браузерде тамак үчүн 640×448 px / 97 876 байт WebP, логотип үчүн
256×179 px / 16 262 байт WebP болду. 360 px экранда форма батты; KY/RU которгуч,
жүктөө прогресси жана сактоо текшерилди. Wrangler R2 симуляциясында жаңы файлдар
200, алмаштырылган эски файлдар 404 кайтарды. Убактылуу тест беттери жана аккаунттар
негизги локалдык базадан өзүнчө түзүлүп, текшерүүдөн кийин тазаланды.

## Кардар менюсу жана офлайн иштөө

`GET /{slug}` `published_menus.slug` уникалдуу индекси аркылуу **бир катарды,
бир SQL сурамы** менен окуйт. `cafes` менен JOIN, сессия текшерүү, менюну кайра
эсептөө жана R2 суроосу бул маршрутта жок. Сүрөттөр өзүнчө `/img/:key` менен келет.
Төртүнчү миграция даяр менюга `slug` жана `is_active` кошот; кафе токтотулганда
же дареги өзгөргөндө бул талаалар ошол эле D1 транзакциясында жаңыланат.

Жооптун кэши: `public, max-age=60, stale-while-revalidate=86400`.
Worker кошумча Cloudflare Cache API'ге 60 секундга сактайт; edge кэши урулса,
D1 такыр окулбайт. Жок/токтотулган/жарыяланбаган меню 404 жана `no-store` берет.
Cloudflare edge тармагынын ишин булутка деплойдон кийин өзүнчө өлчөө керек;
азыр Wrangler'дин локалдык чөйрөсү текшерилди.

Кардар KY/RU которгондо жаңы бет жүктөлбөйт: эки тилдин `data-lang` тексттери
CSS менен көрсөтүлөт. Тандоо `localStorage`'те сакталат; биринчи ачылышта
`cafes.default_lang` колдонулат. Орусча текст бош болсо кыргызча көрсөтүлөт.
Тамактын курамы стандарттуу `<details>` менен ачылат. «Бүттү» тамак күңүрт
болуп, баасы сызылат. Сүрөттөрдө width/height, lazy жана async decoding бар.

`public/sw.js` меню менен сүрөттөр үчүн stale-while-revalidate колдонот.
Биринчи каттоодон кийин ошол бет жана анын lazy сүрөттөрү фондо кэшке алынат.
Ошондуктан офлайн колдонуу үчүн биринчи ачылышта сүрөттөрдүн сакталуусуна
убакыт бериңиз. Экинчи сканда ошол меню интернетсиз ачылат. Админ беттери,
логиндер, пароль жооптору, POST сурамдар жана бөтөн сайттар кэштелбейт.
Жаңы меню версиясы табылса ачык бет жаңыланат; көрүнүп турган бет мүнөт сайын
жаңыртууну текшерет. Интернет жокто акыркы сакталган меню көрсөтүлөт.

Мурда түзүлгөн кафелерди бул этапка өткөрүүдө:

```sh
npm run db:migrate:local
npm run menu:rebuild:local
npm run dev
```

`menu:rebuild:local` локалдык даяр HTML'ди кайра түзөт, версияларды көтөрбөйт.
Бул скрипт `--remote` режимин кабыл албайт.

## QR кодду жүктөө

1. Owner болуп кириңиз же супер админден «Кафеге кирүү» басыңыз.
2. Башкы админ экрандагы «QR код» шилтемесин ачыңыз.
3. Кафенин толук шилтемесин текшерип, SVG же PNG жүктөңүз.

SVG — өлчөмүн чоңойтсо да тактыгын жоготпогон вектор. PNG кеминде 2048×2048 px,
300 dpi метадайындары менен берилет. Ак четин кыркпаңыз жана басмадан кийин
телефондон сынаңыз. QR төрт модулдук ак чет жана Q деңгээлиндеги ката оңдоону колдонот.
Ал учурда ачылган сайттын доменин жана кафенин slug'ун камтыйт. Localhost QR'и
телефондун өзүнө багытталат; чыныгы басма үчүн HTTPS сайттан кайра жүктөңүз.
Домен же slug өзгөрсө мурдагы басылган QR'ди да алмаштырыңыз.

QR серверде чакан `uqr` пакети менен түзүлөт; браузерге QR китепкана жүктөлбөйт.
PNG Workers'тин өзүнүн `CompressionStream` API'си менен жасалат. Коддорду
ошол кафенин owner'и жана супер админ гана жүктөй алат. Автоматтык тесттер эки
форматты өзүнчө `jsqr` сканери менен окуп, шилтемесин салыштырат.
[QR бетинин телефон көрүнүшү](reports/qr-mobile.jpg).

## Акыркы текшерүү жана тейлөө

```sh
npm test
npm run typecheck
npx wrangler deploy --dry-run --outdir .wrangler/build-check
```

`--dry-run` булутка эч нерсе чыгарбайт: жыйноону гана текшерет. `npm test`
баа/slug, CRUD, авторизация, сүрөт, коомдук меню, кэш, офлайн, QR жана толук
кабыл алуу сценарийлерин өзүнчө локалдык D1/R2 аркылуу текшерет.
[Definition of Done отчёту](reports/definition-of-done.md) бардык 12 пунктту,
өлчөөлөрдү жана деплойдон кийинки текшерүүлөрдү камтыйт.

Локалдык база `.wrangler/` ичинде. Аны өчүрсөңүз, жергиликтүү аккаунттар,
сүрөттөр жана менюлар жоголот. Булуттагы маалымат үчүн D1 экспортун жана R2
резервдик көчүрмөсүн өзүнчө уюштуруңуз. Логдорго пароль, cookie же сыр жазбаңыз.
